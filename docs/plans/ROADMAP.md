# Дорожная карта

Путь проекта по направлениям работы: что уже сделано и что впереди. Отмеченный пункт сделан и есть в репозитории; неотмеченный — впереди; пометка «в работе» значит, что пункт начат сейчас. Порядок между направлениями не фиксирован. Пункты, которые впереди, — задачи, а не принятые решения: решения автора — в [VISION.md](VISION.md), подробная история изменений — в [CHANGELOG.md](../../CHANGELOG.md).

## Путь в двух словах

Работа началась 29 октября 2026 года с подготовки проекта к работе с агентами. Затем был разобран эталонный стиль Scapes и написана его библия — свод правил, по которому карточки можно рисовать без образцов перед глазами. На этой основе построены цикл одной карточки (запрос из библии, генерация, обработка, проверки, перегенерация), наборы и коллекции, веб-редактор и проектные скиллы. Сейчас фабрика умеет делать карточки, наборы с вариантами и коллекции из 16 наборов — и по просьбе к агенту, и кнопками в редакторе. После ревью автора редактор переделан по одобренному макету и говорит на двух языках; впереди — подготовка репозитория к публикации.

## Арт-стиль Scapes

- [x] Разбор эталонного стиля: как отдельные предметы складываются в набор (идея, подбор, категории) и как они нарисованы; связь редкости (звёзд), категории и прорисовки; виды рамок.
- [x] Библия стиля, принятая автором, — набор документов в `styles/scapes/` ([вход и карта библии](../../styles/scapes/README.md)): базовые правила, цвет, фоны, прорисовка, композиция, персонажи, наборы, чеклист, фразы для запроса. По ней можно генерировать без образцов; она охватывает все виды карточек, включая золотые карточки с персонажами.
- [x] Все 160 эталонных карточек с указателем: у каждой — фон, опора, положение, ракурс, персонажи; по указателю подбираются образцы стиля к запросу.
- [x] Выяснено, обрабатывались ли оригиналы после отрисовки: у большинства наборов есть след лёгкой резкости ([RENDERING.md](../../styles/scapes/RENDERING.md)); лёгкая резкость вошла в обработку.
- [x] Проверки библии как код ([checks/README.md](../../styles/scapes/checks/README.md)): все эталоны проходят, кроме исключений, названных в библии.
- [x] Опорные портреты пятерых персонажей в полный рост — образцы для сцен, чтобы персонажи выглядели одинаково.
- [x] Шаблоны окон набора: большое окно в четырёх цветах, малое окно, гранд-окно; золотые и кристальные рамки, как в эталоне.
- [x] Правила наборов и коллекций и настройки обработки стиля — данными, которые читает программа.
- [ ] Пестрота сцен: проверка для сцен пока только предупреждает — сцены её ещё надёжно не проходят.

## Генерация карточки

- [x] Генерация в нужном стиле проверена на пробах; модель по умолчанию — Nano Banana 2.1 (выбор автора по пробам), запасная — GPT Image.
- [x] Запрос к модели собирает программа из фраз библии и прикладывает образцы стиля; человек промпты не пишет. Запрос описывает, что нужно получить, а не перечисляет запреты.
- [x] Профиль каждой модели: какие пропорции принимает, сколько образцов, как ей писать запрос. Кадр заказывается не выше карточки, обрезаются только бока.
- [x] Источники изображений: OpenRouter, Google AI Studio и Codex CLI по подписке (без оплаты за картинку). Адрес подключения меняется в настройках, список доступных моделей картинок выдаёт команда фабрики.
- [x] Обработка после генерации: обрезка до 430 × 480, резкость, яркость, насыщенность, подъём теней. Программа подбирает параметры под каждую карточку в границах стиля; тот же код работает в редакторе, поэтому предпросмотр совпадает с карточкой.
- [x] Самопроверка: автоматические проверки библии, контур главного предмета, взгляд смотрящей модели (тот ли предмет и постановка, нет ли незаказанного — например, лиц у вещей). Не прошла — программа генерирует заново в пределах числа попыток и потолка расходов.
- [x] Просьбы к готовой карточке: перегенерировать или отредактировать с пожеланием, подкрутить обработку, принести свою картинку (её проверяют так же строго), сделать карточкой любую из версий.
- [x] Смотрящая модель находит и ошибки рисунка (рука, взгляд, повторяющиеся части); перегенерация учитывает найденное без пожелания человека; из нескольких версий смотрящая модель выбирает лучшую, между версиями без ошибок — «лучше как карточка», рядом с эталонами той же постановки (решения автора по ревью).
- [ ] Локальная модель как источник изображений: адрес подключения меняется, но с локальной моделью фабрику ещё не проверяли.

## Наборы и коллекции

- [x] Набор по теме и свободным пожеланиям: агент или текстовая модель пишет план из 10 карточек по правилам стиля — редкость, рамки, категории, места сцен. Программа проверяет план и возвращает ошибки на исправление, модель ещё раз перечитывает готовый план.
- [x] Несколько вариантов набора за один запуск, число вариантов задаётся; пожелания ложатся в описание каждой карточки.
- [x] Коллекция из 16 наборов (последний — гранд-набор): одной кнопкой или по набору; можно собрать только недостающие наборы или ещё по варианту каждого.
- [x] Неповторение: заметные предметы, подписи и названия наборов в коллекции не повторяются.
- [x] Хранилище карточек коллекции: карточки могут жить вне наборов и переноситься между местами и наборами; свободные карточки на тему — от 1 до 10 за запуск.
- [x] Надёжность запусков: прежние планы набора сохраняются, при остановке готовое не теряется, расходы держатся в пределах, при проблеме с ключом запуск останавливается с понятным сообщением.
- [x] Экспорт: картинки PNG по понятным папкам и архивы ZIP, кнопка «Открыть в папке».

## Работа с продуктом: агент и редактор

- [x] Агентский путь: человек просит агента («сделай 20 карточек про…», «сделай набор», «сделай коллекцию»), агент работает командами фабрики в терминале — в её папке или из своей, если дать путь к фабрике.
- [x] Одно ядро операций для агента и редактора: агенту доступно всё, что человеку в редакторе.
- [x] Вживую: созданное агентом само появляется в открытом редакторе; агент может открыть редактор и показать результат; платные команды агента без своего ключа выполняются в запущенном редакторе с его ключом.
- [x] Веб-редактор запускается локально: коллекции → коллекция → набор → карточка. Набор показан в окне шаблона, цвет окна переключается, карточки перетаскиваются, рядом — хранилище коллекции.
- [x] Панель карточки: версии карточки, результаты проверок и замечания смотрящей модели, ползунки обработки, перегенерация и правка с пожеланием.
- [x] Создание коллекций, наборов и карточек из редактора; «Сформулировать» — текстовая модель превращает наброски продюсера в готовый текст.
- [x] Настройки: сервис, модели, временный ключ, который живёт, пока запущен редактор; статус ключа на виду; расходы на картинки, текст и взгляд модели.
- [x] Дизайн-система редактора, принятая автором ([README](../../editor/design-system/README.md)): нейтральный серый фон, зелёный — одно главное действие, светлая и тёмная темы.
- [x] Интерфейс переделан после ревью автора по одобренному макету: раскладка экранов, настройки по разделам, один общий экспорт в верхней панели, лист карточки с понятными находками, кнопка «Выключить редактор».
- [x] Интерфейс на русском и английском, включая сообщения программы.
- [x] Настройки набора (название, тема, пожелания, вид и цвет окна, звёзды, рамка и подпись каждого места) и сборка набора руками из карточек хранилища; пустое место можно сгенерировать.
- [ ] Редактирование стилей в редакторе; возможно — редактирование шаблонов (не решено).
- [ ] Редактор на хостинге: сейчас он открыт только на своём компьютере.

## На будущее

Идеи, которые сейчас не нужны, но было бы хорошо сделать.

- Сменные стили: человек загружает свои референсы; в редакторе виден весь стиль (библия текстом и референсы), можно описать свой стиль и генерировать в нём.
- Переопределение элементов стиля: заменить отдельные элементы (состав персонажей, фирменные знаки на предметах и т. п.), не меняя стиль целиком, — в редакторе и в агентском пайплайне.
- Настраиваемое окно набора: свой редактируемый шаблон, где можно задать редкость, рамку, текст и цвет каждой ячейки.
- Единая точка входа во внутренние сервисы компании: портал, где сотрудник выбирает сервис под свою задачу; создание коллекций — один из сервисов. Зачем: продукт не просто удешевляет работу, а снимает часть работ сотрудника целиком.
- MCP-сервер сервиса: сервис на сервере с авторизацией, сотрудник добавляет в свой аккаунт ключ поставщика инференса (OpenRouter или другого) и подключает MCP к любому агенту или чату (ChatGPT, Claude в браузере и т. п.) — чтобы создавать и, возможно, править карточки, наборы и коллекции из обычного чата, без интерфейса сервиса.
- LoRA-адаптер стиля для локальной бесплатной модели (например, Z-Image Turbo или Flux): материала эталона для обучения хватает, а генерация через такую модель резко снизит затраты. Сейчас не обучаем: своей видеокарты нет, аренда дорогая.
- Хостинг с любым входом: корпоративная SSO, Cloudflare Zero Trust и т. п.
- Агентский режим внутри редактора на хостинге: через OpenRouter или любой адрес подключения из настроек.
