# MAP.md — project map

Navigation for an agent: where things live and which file to start from. It is not a list of every file and not a copy of the documents; look at the current contents of a folder before working in it.

Update this map in the same task when an area, an entry point, a system file or a significant document is added, moved or removed. Do not describe what is planned as if it already exists.

## Entry points

- `AGENTS.md` — the agent's rules, what the project is, the task → skill table, commands.
- `README.md` (English, main) and `README.ru.md` (Russian) — the same text for a person from the street: what the factory is, install and start, the key, who draws, the editor, export, working through an agent, stopping, the license.
- `LICENSE` — MIT for the code and documents; the reference images in `styles/scapes/references/` are excluded.
- `ccf.mjs` — the factory's commands for an agent in the terminal (`node ccf.mjs --help`): `card make`, `card regenerate`, `card wish`, `card title`, `card edit`, `card adjust`, `card import`, `card choose`, `card prompt`, `card check`, `cards make`, `models`, `credits`, and from `core/set/cli.js` `set plan|check|save|make|sheet`, `collection plan|check|make`, and from `core/store/cli.js` `collection list|create|show`, `export`; thin calls of `core/` operations, `--json` for agents.
- `docs/plans/VISION.md` — the author's accepted vision of the project (not a log).
- `docs/plans/ROADMAP.md` — the directions of the work on the product: what is done and what is left, with links to plans.
- `docs/plans/` also holds local working documents ignored by Git (handoff, brainstorm logs, source materials): see «Local working documents» in `AGENTS.md`.

## Product

- `styles/` — art styles the product generates in; one per folder. `styles/scapes/` — the first style: its style bible (`README.md` is the entry point and map of the bible documents); `references/` — all 160 reference cards with an index (`references/README.md`); `characters/` — the five anchor portraits of the characters (full length, grey backdrop, unprocessed model images; index and what is canon vs invented in `characters/README.md`), attached to scenes by the prompt assembly; `checks/` — the automated part of the bible's checks (`explain.json` — each check in plain words, Russian and English, for the editor's card sheet; `check-card.mjs` with `thresholds.json`, the control-run spec of the references, `adjust-trial.mjs` for post-generation adjustments with the product's own processing; both read images with `sharp`; entry point `checks/README.md`); `processing.json` — the style's post-processing settings (neutral, starting settings per model, sharpening bound, the bounds and checks of the per-card search): the one place for their numbers; `prompt-assembly.json` — how the program assembles a card's image-model prompt from the bible's marked fragments (which fragment for which staging, slot filling, staging vocabulary of a card order, reference-card picking); `windows/` — the set-window templates and `windows.json`, their geometry in template pixels (where each card goes under the frame, the title, number and caption boxes and lettering colours) — the one source the editor lays a set out by: the large window in four colours (blue, violet, crimson, orange; placeholders removed, picture openings transparent) with gold frame images per slot (`frames/`); the small window (`small/`: the same four templates without stars, a star image per star count, gold frames without star holes); the grand window (`grand.png`, crystal frames, one colour); `set-rules.json` — the checkable set and collection rules of `SETS.md` as data (window layouts, staging rows and presets, shares, the reference collection curve, the planning prompt's fragment ids and glue); `research/` inside is local, ignored by Git.

- `core/style/` — the card order and its prompt: `card-order.js` (`CardOrder` typedef, `validateOrder`, `orderOutput`; besides a card, the order kind `character-sheet` — an anchor portrait of one character, rules in `prompt-assembly.json` → `kinds`), `prompt.js` (`buildPrompt`: order → prompt, fragments used, reference cards to attach), `fragments.js` (parses `<!-- fragment: id -->` markers in the bible, fills slots), `assembly.js`, `references.js`, `style.js`; fields and formats for agents: `core/style/README.md`. Tests: `tests/style-prompt.test.mjs` (with the five pilot cards as orders in `tests/style-pilot-orders.mjs`), `tests/style-sheet.test.mjs` (character sheets).

- `core/card/hero.js` + `core/image/segment.js` — the hero's outline for the style's checks: `findHero` cuts the outline inside a box from an agent or a person, or from the vision model of `settings → vision` (asked on the card and its mirror image; agreement → confidence), by GrabCut (`segment.js`, browser-safe, also for the editor); `checkCard(card, { outline })` takes it; the card loop finds it for every attempt (`card.hero.png`). Tests: `tests/core-hero.test.mjs`.
- `core/card/pick.js` — with several versions of a card the vision model sees them all at once and picks the best, with a reason.
- `core/card/fix.js` — a new attempt learns from the last: the text model's correction from an attempt's findings, appended to the next prompt (the loop and `regenerateCard`), and `proposeCardWish` — a wish proposed for the editor's field or `ccf.mjs card wish`.
- `core/card/look.js` — the vision model's look at a finished card (`lookAtCard`): the order's words (the assembled prompt) and the style's checklist for eyes against the picture — wrong subject or staging, unordered additions such as faces on objects, missing costume items; settings → `look` (which questions block). The loop runs it on every attempt when the provider holds a key (`look.json`). Tests: `tests/card-loop.test.mjs`.

- `core/image/` — image processing: `prepare.js` (Node, `sharp`: `prepareCard` turns a model image into card pixels of the size the caller gives — scaled down to the card with only its sides cut, equally (a frame taller than the card loses only its bottom and is reported as `cutBottom`), Lanczos-3; without a size it keeps the image's own; `encodePng`) and `adjust.js` (browser-safe pure functions: `adjust(pixels, width, height, settings)` — brightness, shadow lift, saturation, luma unsharp mask; the same code for the pipeline and the editor preview). Tests: `tests/core-image.test.mjs`.

- `core/card/` — the production loop of one card: `make.js` (`makeCard`: order → prompt → generation → `core/image` → the hero outline (`hero.js`) → the style's checks → the vision model's look (`look.js`), regenerating within the attempt limit and the spend cap, into the collection's pool through `core/store`, optionally into a set slot; a person's or an agent's requests on a card: `regenerateCard` with a wish, `editCard` (the model image as the input image), `adjustCard` (processing by hand, or reset to the program's own), `importImage` (an image the agent drew with its own tool, checked as strictly as a generated one), `chooseAttempt` (any version — attempt — becomes the card), `orderPrompt` (what the agent needs to draw it: prompt, references, frame); `recheckCard`; `providerFrom` picks the provider from the settings, with the fallback model tried in the same attempt when the main one fails; the outline policy is in its header; an order kind's `orderOutput` can keep the model's frame, skip the pixel checks and ask for its own aspect ratio), `check.js` (plugs in a style's checker `styles/<style>/checks/check-card.mjs`), `tune.js` (per-card post-processing search: saturation, brightness, the shadow lift for scenes, sharpening within the style's `processing.json` bounds, against the bible's aims), `card-file.js` (the one description of the card folder and `card.json`). Tests: `tests/card-loop.test.mjs`, fake provider.

- `core/text/draft.js` — the editor's text help: a producer's rough notes in a free-text field (collection description, set theme and wishes, card wish) → the finished text, with the text model of `set.plan`; prompt words in `settings/defaults.json` → `text.help`; the cost goes to the spend ledger. Tests: `tests/text-draft.test.mjs`.

- `core/say.js` — a message a person reads as data (`code` + `params`) beside its Russian text, so the editor says it in the page's language (`editor/web/said.js` holds the English words).
- `core/settings.js` + `settings/` — the factory settings (tests read a copy of `defaults.json` only, via `CCF_SETTINGS_DIR` set in `tests/root.mjs`, never the person's `local.json`; the copy names a key variable nobody sets and no editor, so no test reaches a real key): `settings/defaults.json` (tracked; provider choice and values, attempts and spend cap per run, post-processing overrides per model; what each means is in its `_about`) and `settings/local.json` (personal override, ignored by Git; the editor's settings write it through `saveLocalSettings`, which keeps only what differs from the defaults). The API key is never in settings.

- `core/set/places.js` — what a set's window shows on each place (a person's stars and frame over the plan, else the window kind's default; `placesOf`, `placeChoices`), `setPlace`, and `fillPlace` — a card for an empty place (the plan's order not yet used, or one order written by the text model for a hand-made set); an empty hand-made set is `set create`.
- `core/set/` — planning and making sets and collections by the style's rules: `plan.js` (`SetPlan`, `validatePlan`, `validateCollection`), `planner.js` (`planSet`, `planCollection`: the text model writes the plan from the `SETS.md` fragments, errors go back for repairs), `make.js` (`makeSet`, `makeCollection`: plan into `set.json`, cards through `core/card` in parallel under one spend cap), `cards.js` (loose cards into the collection's pool: `planCards` — the text model writes N orders from the same fragments without the window, checked by the style —, `makeCardsInto` for `ccf.mjs cards make` and the pool's «Создать карточки»), `sheet.js` (a contact sheet of a set), `cli.js` (`setCommands` for `ccf.mjs`); format and rules: `core/set/README.md`. Tests: `tests/set-plan.test.mjs`, `tests/set-make.test.mjs` (fixture `tests/set-fixtures.mjs`).

- `core/store/` — the store of the factory folder: collections, sets, the collection's card pool, moving cards between slots, deleting to the OS trash, export (PNG folders and ZIP, own writer `zip.js`), «open in folder», live events for the editor (`watch.js`); atomic writes; what was spent, by kind (`spend`: images and vision from the cards, text from the ledger `collections/spend.jsonl` that `recordSpend` appends to). `cli.js`: the collection and export commands of `ccf.mjs`. Entry point `index.js` (the Store API listed in `core/README.md`), `createStore({ root })` for another folder; the layout and the formats of `collection.json` / `set.json`: `core/store/README.md`. Tests: `tests/store-collections.test.mjs`, `tests/store-export.test.mjs`, `tests/store-watch.test.mjs`, `tests/cli-collections.test.mjs` (the commands as a child process over a temporary store, `CCF_COLLECTIONS_DIR`) (shared setup `tests/store-helpers.mjs`).

- `collections/` — the factory's output, ignored by Git (`_export/` — the export of all collections at once): `<collection>/collection.json`, `sets/<set>/set.json`, the card pool `cards/<card>/` (`card.json`, `card.png`, `attempts/<n>/`; the card folder: `core/card/card-file.js`), `export/` (layout: `core/store/README.md`). Folders without `collection.json` are not collections (the early pilot runs were moved into the pool layout on 2026-10-30).

- `core/providers/` — the services and image providers (`catalog.js`: the real model lists of OpenRouter and Google AI Studio with what each model takes and gives, for the editor's model pickers); every value comes from the caller (the factory's settings, `settings/defaults.json` → `provider`): `preset.js` (the API presets: `presetOf` — the service of `provider.preset` and its block `provider.<preset>`, `apiOf` — its calls, `runSettings` for `--provider` and `--model`), `models.js` (each model's profile from `provider.models`: the ratios it accepts — a model lacking the card's ratio is asked for the one closest to the card and cut —, reference images, request fields, `sameAs` = the same model at another service), `openrouter.js` (`generateImage`, `askVision`, `listImageModels`, `getCredits`, `loadApiKey`, the shared `request`; OpenRouter-compatible endpoint), `gemini.js` (Google AI Studio, the Gemini API's generateContent: `generateImage`, `askVision`, `complete`, `listImageModels`; cost from the answer's tokens and `provider.google.prices`). Tests: `tests/provider-openrouter.test.mjs`, mocked fetch; `tests/provider-gemini.test.mjs`, a fake Gemini server. `codex-cli.js` (`generateImage` with the same contract through `codex exec` under the ChatGPT subscription, no per-image payment). `openrouter-text.js` (`complete`: one chat completion of a text model, JSON mode; the planning model of `core/set`). Tests: `tests/provider-codex-cli.test.mjs`, mocked spawn.

- `editor/` — the web editor for a person (skill `ccf-editor`): `server.mjs` — the local server (`node editor/server.mjs [--port N] [--open COLLECTION[/SET]] [--no-browser]` in the foreground; `node ccf.mjs editor [--open …] | --stop` in the background for an agent; 127.0.0.1 only, the token of the run on every API call; a running editor is reused); `server/ops.js` — the JSON API, one entry per core operation (live list `GET /api/ops`); `server/jobs.js` — long operations with progress, waiting and cancelling; `server/key.js` — the keys, one per service's key variable: permanent (environment / `.env`) and temporary, held only in memory; `remote.js` — how a local agent finds a running editor (`.ccf/editor.json`, ignored by Git) and calls its operations with its key; the paid `ccf.mjs` commands go through it when there is no key here; `web/` — the page (`app.js` the shell and router collections → collection → set, the card as a sheet; `screens/` (collections, collection, pool, set; `patch.js` — screens updated in place on live events), `panels/`, `window.js` a set over the style's window template, `editor.css`). Tests: `tests/editor-server.test.mjs`.
- `editor/design-system/` — the editor's design system: `DESIGN.md` is the single source of every value (design.md format + `x-tokens` blocks, light and `-dark` twins); `tokens.js` turns it into CSS variables (reads the front matter with its own subset parser `front-matter.js`); `components.css` — the controls and editor patterns; `fonts/` — bundled woff2 with licences; `example/` — the live board (serve the repo root, open `/editor/design-system/example/`); `README.md` — for a person.

## Agent setup

- `agents/skills/` — editable sources of project skills (`ccf-<name>`); the task → skill table is in `AGENTS.md`. Using the factory (also from another folder): `ccf-make-cards`, `ccf-make-sets`, `ccf-review-cards`; developing it: `ccf-core`, `ccf-style`, `ccf-editor`. `.claude/skills/` and `.agents/skills/` are generated copies, `agents/manifest.json` records them.
- `agents/README.md` — how Claude Code and Codex work in the project: skills, hooks, permissions, optional MCP.
- `agents/harnesses/`, `agents/browser/` — optional MCP examples (Playwright, Context7, Tavily) and browser profiles for Playwright.
- `.claude/` — `settings.json` (auto memory off, compaction at 500k, agent teams, no nested helpers, permissions, hooks), `hooks/` (`handoff.mjs`, `agent-run.mjs`, `regex-guard.sh`, `shared.mjs`), `statusline.mjs`; `runs/` — helper journals, ignored by Git.
- `.codex/config.toml` — `project_doc_max_bytes` raised so `AGENTS.md` is not truncated.

## Installation and launch

- `run.command` (macOS, double-click), `run.sh` (Linux), `run.bat` (Windows) — the one-click launchers: check that Node exists, run `tools/setup.mjs`, then start the editor (`editor/server.mjs`), which opens the browser.
- `tools/setup.mjs` — first-run setup: Node version against `package.json` engines, `npm install --no-package-lock` when `node_modules` is missing or stale (stamp `node_modules/.ccf-install.json`), checks that `sharp` loads. `package-lock.json` is deliberately not tracked (see the header of the script and `CHANGELOG.md`).
- `package.json` — the only dependencies (`sharp`; `typescript` as dev). `tsconfig.json` — the type check of the product code (`core/**/*.js`, JSDoc types, no build); run by `tools/check.mjs`.

## Tools and checks

- `tools/check.mjs` — the project check: `agent-doctor`, `sync-agents --check`, `tests/*.test.mjs`, and the type check of `core/` (skipped while packages are not installed).
- `tools/agent-doctor.mjs`, `tools/sync-agents.mjs` — diagnosis of the agent setup and generation of native skill copies.
- `tools/trash.mjs` — the only sanctioned way to delete: to the OS trash, only inside the project and Claude Code's temporary folders.
- `tools/cli-args.mjs` — the shared command line of the scripts (`--help`, refusing unknown options).
- `tests/` — tests of the agent setup, hooks, status line and tools, and a short run of the Scapes checks.
