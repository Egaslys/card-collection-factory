# Develop the editor

The editor is for the person: check the work at a glance, rearrange cards, adjust a card, change settings, generate without an agent (`docs/plans/VISION.md`: its sections on the web application and on how the product is used — nesting, live updates, the key, export, the feel). It is being built now: read the current files before relying on this skill, they win where the two differ.

## Parts

| Path | What |
|---|---|
| `editor/server.mjs` | the local server: `node editor/server.mjs [--port N] [--open COLLECTION[/SET]] [--no-browser]` runs it in the foreground, alive as long as its terminal (a closed terminal — SIGHUP, or the parent process gone — stops it) (the launchers `run.command`, `run.sh`, `run.bat` run the setup, then this; given options such as `--help` or `--check` they run only the setup); `node ccf.mjs editor [--open …] [--no-browser] [--port N] \| --stop` runs it in the background for an agent, until `--stop` (output in `.ccf/editor.log`). Listens on 127.0.0.1 only; every API call carries this run's token. Its header lists what it serves; `startEditor()` and `runningEditor()` for code |
| `editor/server/ops.js` | one entry per core operation, mapping the request's JSON to the core call; `job: true` = long, run by `jobs.js`. The live list: `GET /api/ops` of a running editor |
| `editor/server/jobs.js` | long operations: progress to every page, waiting, cancelling through an `AbortSignal` |
| `editor/server/key.js` | the keys, one per key variable (each service's `keyEnvVar`): permanent from the environment / `.env`, temporary only in this module's memory, never in `process.env` (a child process such as Codex would inherit it); switching the service never carries a key over; the page sees only their status (permanent, temporary, none), never any part of a key |
| `editor/remote.js` | an agent's way in: `findEditor()` reads `.ccf/editor.json` (exists while the editor runs, ignored by Git), `callEditor(editor, op, args, {onLog, signal})` runs an operation with the editor's key and waits for a job; `hereOrInEditor()` is how the paid `ccf.mjs` commands run here or, with no key here for the run's service, in the editor with its key for that service — a paid op's arguments must cover its command's options (`--provider` and `--model` included) |
| `editor/web/` | the page: `app.js` (the top bar in blocks — export on the left with its own accent, spend, key, the running-jobs count, theme, RU/EN, the labelled settings button on the right; the breadcrumbs row above the screen; the router collections → collection → set, the card as a panel, live updates; a screen gives `where` / `html` / `mount` / `affects` and draws its own header actions, no `primary`; event `bye` = the editor was switched off), `i18n.js` (two languages: every text a person reads comes from its module's `words({ru, en})`, `plural`; the choice is remembered in the browser), `api.js`, `state.js`, `ui.js`, `window.js` (a set over the style's window template in the window of its kind — set.json `window.kind`: the main window or a `families` entry such as small or grand —, geometry, frames and stars from `styles/<style>/windows/windows.json`), `hints.js` and `hints-ui.js` (the hints, see Invariants), `screens/`, `panels/`, `editor.css` |
| `editor/server/codex.js` | whether Codex is ready to draw (`codexStatus` of `core/providers/codex-cli.js`: ready, login, missing, error; null when the settings do not have Codex draw), asked at start, after `saveSettings` and when a page connects; the page gets it in the `hello` event and a `codex` event, `health` returns it too |
| `editor/design-system/` | the accepted look: `DESIGN.md` is the single source of every value, `tokens.js` turns it into CSS variables, `components.css` holds the controls; `README.md` for a person; its open decisions at the end of `DESIGN.md` |

## Invariants

- **Product logic lives in core.** An editor feature that needs a new capability is a core operation first (ccf-core), then its `ccf.mjs` command, then its entry in `ops.js`: the agent can do everything the person can.
- **The preview equals the card**: the page imports `core/image/adjust.js` itself (the server's shared files), never a copy.
- **Card sheet** (`panels/card.js`): a plain-language summary (all right / could be better / needs attention — soft tones by `DESIGN.md`: grey and amber, red only for a card that did not work out) with findings grouped by who found them (the automatic checks, the vision model); every check's words come from the style's `checks/explain.json` in the page language (`getCard.explain`), and «All measurements» shows the measured value against the check's `norm`/`limit` with the explain.json units (`measure.js`), the code only as a grey label; redraw needs no wish (it fixes the findings), edit sends the version's model image; the wish field's text help is `proposeCardWish`; versions flip without redrawing the sheet; the vision model's pick reason is shown. `bindTextHelp(root, about, ask?)`; `draftText` gets `language`, and an empty field gets a text proposed from its context.
- **The page shows what the checks say**: the card panel's counts come from `check.needsEyes` (not recomputed from `fails`), and the vision model's issues (`look.issues`), or that it found none, are shown — all for the version the panel shows (every attempt is a version; arrows flip them, the "make it the card" button is `chooseAttempt`). Spend is shown split by kind (`spend` op: images, text, vision) in the top bar and per version in the card panel; the key is shown only as a status. Free-text fields carry the text help (`textHelp`/`bindTextHelp` in `ui.js`, op `draftText`); the card's wish field proposes a wish from the version's findings (op `proposeCardWish`), and `regenerateCard` needs no wish (`n` = the version whose findings to fix). Settings screen: the service (`provider.preset`) and its key — one key per service, a temporary one held per key variable —, who draws (`provider.use`), the chosen service's models (`provider.<preset>.*`: image, fallback, vision, text, endpoint, key variable); `look.use` and the vision model in its own section. An emptied number field goes back to its default (`saveSettings` `reset`); a number below the field's `min` is refused on the page, a non-number by `core/settings.js`. The editor shows no spend caps — not in the create sheets, not in settings (the author's decision, 2026-10-31: the person limits spend on their provider's key; the caps in settings are a safety net for agents and the CLI); a job may still say a card was skipped by a cap, or that the key stopped the run (`warnings`). The collection screen's build-all button, in a collection with sets, offers «only the missing» or «one more variant of every place» (`buildCollection` `mode`, `core/set/README.md`).
- **Live**: the page follows the store's events (`/api/events`), so whatever an agent writes appears by itself; an open card sheet is drawn over in place (never closed and reopened), keeping the typed wish, the mode, the scroll and the focus.
- **One card, one action at a time from the panel**: the card panel holds its actions (send a wish, apply or reset processing, make a version the card, own image) while a long operation runs on the card — a job of this card, or anything the card summary's `busy` names (a set's job, an agent's `ccf.mjs`) — and while one of its own calls is under way. The core keeps every result either way (`core/card/card-file.js`).
- **The key never leaves the editor process**: not to disk, not to logs, not to the page.
- **Look**: every value comes from `DESIGN.md` through `tokens.js`; markup uses the classes of `components.css` (and `editor.css`); nothing loads from the network. Neutral grey around cards, green for the one primary action per screen, light and dark themes.
- No build and no framework; texts a person reads are in Russian and English through `i18n.js`, code comments English. Core texts (job log lines, errors) are still Russian only: the page shows them as they are.
- **Screens** (`screens/`): `getSet` and `getCollection` give each set `shown {places, choices, planned}` (ops.js `withPlaces`); screens apply live events in place through `screens/patch.js` (the shell's `update` hook); the open place and cards picked for the export carry a `.wnd__ring` over the window template; place panel (stars, frame, caption via `setCardTitle`, an empty place → `fillPlace`), set settings, variants «N of M», «i» hints instead of help lines.
- **How a job ended** (`jobEnding` in `ui.js`): by the job's `outcome {made, of, reason}` — nothing drawn is a failure-looking «Nothing drawn» with the reason, part drawn «Done: k of N», all drawn with remarks «Done, with remarks»; the status stays `done` for agents. The set window keeps whole on screen (`keepWhole` in `window.js`).
- **Server texts in the page language**: an error from the server carries `said` next to `error`, and `api.js` words it (`saidText`), so toasts from `attempt()` need nothing; a finished job has `errorSaid` and `warningSaid[]`, journal lines have `say` — show them through `saidText` / `logText` (`editor/web/said.js`), never `j.error` or `l.text` raw. In Russian `said.js` returns core's text; the English words of codes live only in `said.js`. The export window passes `language: lang()`.
- **Shared pieces** (`ui.js`, `state.js`): `confirmDialog({title, text, yes, no})` for destructive actions — the confirming button on the left, the refusing one on the right (the author's decision), focus on the refusing one; `tip()` — the «i» hints; `app.selection` — cards picked with ⌘/Ctrl-click for the export; job words from a job's `about` and log lines' `say` (`editor/server/jobs.js`, `aboutOf` in `server.mjs`), never money in the queue. Ops `listModels` (the service's real model list, cached per service, `core/providers/catalog.js`) and `stopEditor({force})`. One export window from the top bar, its «what» preselected by the screen. `[hidden]` always wins over a component's `display`.
- **Hints** (the author's decisions of 2026-10-31 on the approved mockup): empty states teach the first step (part of their screen, always shown). The quiet "Next step" line and a first-use pill (drag a card in; then click a card in the window) sit at the end of the main section's header row ("Window · n/10", "Sets · n") and never add height to it — at most two lines, the label dropped when the row is narrow — because the window and the set tiles keep their size (`keepWhole`); on a phone they take their own line. One step hint per screen, a first-use one first. The first screen's setup card says when the service key is missing or Codex is not ready (`app.key`, `app.codex`) and goes by itself once it is. Which hint shows in which state is pure logic in `hints.js` (`setHint`, `collectionHint`, `setupHints`; tests `tests/editor-hints.test.mjs`): export appears only for a full window with no card "Has problems" (there is no "checked" mark in the data). × hides one hint for good (a toast offers to bring it back); Settings → Look → "Hints" hides all, and "on" brings the hidden ones back. Remembered in the browser like the theme (`ccf-hints`, every access in try/catch); a screen redraws its hints on `HINTS_EVENT` (`onHints`), and the shell sends it when the key or Codex status changes. A new hint: its rule in `hints.js` with a test, its words in `hints-ui.js` in both languages.
- **Firefox** (the author's browser): Playwright's Firefox does not start on this macOS ("Could not find profile folder"); the installed Firefox takes static screenshots headless with its own profile: `/Applications/Firefox.app/Contents/MacOS/firefox -headless -no-remote -profile <scratch>/ffp --window-size=W,H --screenshot out.png URL`.

## Check

- `node tools/check.mjs` must pass.
- A real scenario: start `node editor/server.mjs --no-browser --port 0` — never open the person's browser or use their editor's port. When an editor already runs, this only prints that one's address and starts nothing, so it is not your changed code: run yours with `CCF_EDITOR_FILE` set to a temporary path (a variable meant for tests; `CCF_COLLECTIONS_DIR` for a copy of the data). Open the printed address in Playwright (MCP: `agents/README.md`, «Optional MCP examples»), click through the changed screens in both themes, and watch a change made from the terminal (`ccf.mjs`) appear on the open page. Stop the server you started.
- Tests: `tests/editor-server.test.mjs` (access, files, settings writer and an old `settings/local.json` read in the new shape, `ccf.mjs editor` options, stopping on SIGHUP, `callEditor` against a fake editor).
- Update `MAP.md` and `CHANGELOG.md` when a part is added or moved.
